# 验证记录

验证环境：Windows 11；Codex Desktop 26.810.7004.0；Codex CLI 0.148.0-alpha.9；Node 24.19.0。

- MCP 自检：16 组 initialize、工具列表/调用、资源读取、安全文件预览、真实检测、人工标记、登记与持久化请求全部通过；同一路径升级会合并为一项并保留版本历史。
- 独立入口：`--http` 只绑定 `127.0.0.1` 动态端口，生成 `run/server.json`，通过健康检查、静态首页、列表、检测和人工标记请求。
- HTTP 防护：验证 Host、同源写入、opaque iframe 令牌与精确 CORS、JSON Content-Type、64 KiB 请求体限制，以及静态路径穿越阻断。
- 伴生渲染：验证 `about:blank` 隔离 iframe 不含 `allow-same-origin`，并由私有 CDP pipe 使用 `Page.setDocumentContent` 注入自包含界面。
- 本机 app-server 临时注册验证：`mcpServerStatus/list` 能读取本地 stdio MCP 的中文标题、`ui.resourceUri`、`ui.visibility` 和 `global` entrypoint，元数据未被丢弃。
- UI 资源：CSS/JS 已内联，无 `/assets/...` 外部依赖；MIME 为 `text/html;profile=mcp-app`。
- 隔离：没有写入 Codex 安装目录或 `app.asar`；启停只管理 `mcp_servers.output_items`。
- 可追溯：内部自登记依次选择合法 `CODEX_THREAD_ID`、合法请求 `threadId`、合法显式 `OUTPUT_ITEMS_SOURCE_THREAD_ID`；都不可用时使用 `local-install` 未知来源组，不生成或固化任务 UUID。原始内部请求不能覆盖真实 Codex 当前任务；公开登记缺失或传入非法 UUID 都会失败。长驻 HTTP、companion 与受管 ChatGPT 子进程不会继承一次性安装任务上下文，父安装进程的环境在启动后精确恢复。版本和活动都携带同一来源契约。
- 检测边界：只检查路径、权限和基础文件结构，不自动执行程序。
- 预览边界：覆盖 UTF-8/UTF-16 文本、512 KiB 与 5000 行截断、PNG magic/尺寸、12 MiB 图片限制，以及伪装图片、二进制文本、未登记文件、绝对路径、路径穿越、跨源请求和 opaque iframe token 拒绝。HTML、SVG 与脚本仅返回惰性 `text/plain` 契约。

## 0.5.0 扫描器验收范围

- 历史回填：在没有任务主动调用登记工具的前提下，首次扫描可从 Codex 本地历史中发现有真实产出证据的文件与文件组。
- 后续增量：重复扫描不制造重复项；新增或变化记录由扫描游标继续处理，同一路径的后续修改进入版本历史。
- 任务树：subagent 产出归并到根用户任务，“打开任务”指向该根任务；guardian 和无有效归属的维护任务被排除。
- 只读边界：读取仅覆盖 `state_*.sqlite`、`sessions`、`archived_sessions`、`generated_images` 和 `visualizations`；扫描结果仅写入扩展自己的 `data/scanner.json`、`data/items.json` 和 `logs/events.ndjson`。
- 过滤：`Temp`、缓存、依赖目录和其他明显的运行中间文件不进入产出项。
- 入口：服务启动后可自动扫描；界面“立即扫描”可触发同一扫描流程，并显示进行中、成功或失败状态。
- 文件状态：被发现后又消失的路径保留历史并显示已删除；重新出现后可重新检测。人工状态不会被自动检测覆盖。
- 兼容性：测试应显式覆盖不完整/未知会话事件，解析失败不得修改 Codex 数据或破坏已存在的产出索引。

原生侧栏显示受 Codex 未公开灰度开关影响，不列为本扩展的成功条件。可靠入口是 `打开产出项.bat`；停用与卸载会先验证并结束对应的独立服务进程。

## 0.6.0 文件操作与批量验收范围

- 文件资源管理器：目录直接打开；单文件使用 `/select,` 精确选中；未登记路径与路径越界会被拒绝。
- 资源管理器前置：helper fixture 模式在加载 Shell COM/Win32 前返回，覆盖大小写与尾分隔符规范化、精确目录 HWND 命中、相似前缀/标题拒绝及无匹配错误；断言 `windowMutationAttempted:false`，自动测试不会打开或改变任何桌面窗口。API 分开返回 `launched/foreground/error`，未复核前台状态时顶层 `ok:false`。
- Windows 实机验证契约（仅人工 opt-in）：必须另建独立临时 data root、Codex root 和 workspace，登记其中专用目录与文件后分别调用一次“打开位置”；仅当返回 `foreground:true` 且前台 Explorer 的规范化目录精确等于 fixture 目录才通过。不得使用真实产出或用户目录；验证后先关闭该 Explorer 窗口，再删除临时 fixture。此流程不进入默认自动测试。
- 删除安全：所有删除必须显式 `confirm:true`，生产环境只进入 Windows 回收站；自测仅把目标改名移动到临时 fixture 内的伪回收目录，生产服务不含永久删除产出文件的分支。
- Windows 回收站适配：额外从 Node 以与生产相同的 `powershell.exe -File` 参数方式调用辅助脚本，对隔离临时 fixture 验证中文、空格、逗号路径，以及嵌套单文件、单文件产出、整项目和连续批量项目；同时验证受保护根、授权根越界、错误 JSON 与目录联接均拒绝且目标保留。PowerShell 脚本只包含 `SendToRecycleBin` 生产删除分支。
- 删除粒度：覆盖单文件、整项目和批量项目；父子路径同时选择时只操作最上层目标，并逐项返回结果。
- 保护边界：覆盖驱动器根目录、用户目录、工作区根目录、Codex 数据、扩展数据、扩展目录、网络共享及符号链接越界拒绝。
- 数据保留：删除后产出项、来源、版本、人工标记与活动历史仍保留，系统状态和文件级状态更新为已删除或部分删除。
- 优先级：覆盖单项与批量设置；列表先把已删除项沉到正常项之后，再仅在各自状态桶内按优先级、更新时间稳定排序，自动扫描归并不会覆盖人工优先级。
- 多选界面：覆盖全选、清除、批量检测、批量优先级、批量删除二次确认，以及部分失败摘要。

## 0.7.0 文件大小与层级文件树验收范围

- 文件大小：现存文件返回精确 `sizeBytes`；文件夹返回后代普通文件汇总大小、直接子项数、后代数和完整性标记。
- 产出项总大小：每项持久化 `sizeBytes` 与 `sizeAggregationComplete`；可完整扫描时使用递归总字节数，路径缺失或聚合不完整时返回 `null/false`，普通列表 GET 不重新扫描目录。
- 旧数据迁移：不含大小字段的 `items.json` 首次读取时自动补齐并持久化，已删除且无法恢复大小的历史记录保留为未知。
- 扫描边界：单次递归最多记录 1,500 行、访问 20,000 个节点；触达上限或读取失败时不把部分聚合值标成完整值。
- 文件树交互：初始只显示顶层条目；点击文件夹仅展开其直接子项，再次点击收起；二级文件夹保持独立展开状态。
- 路径操作兼容：展开后的嵌套文件继续使用原始 `relativePath` 执行打开位置和单文件删除。

## 0.8.0 任务分组、启动器与 GitHub 发布验收范围

- 任务分组：同一根任务的多个产出项共享 `taskGroup.key`；subagent 产出归到根任务，生产者信息继续保留；未知来源进入独立兜底组。
- 批量模式：普通浏览不显示复选框；点击“批量操作”后才显示多选与工具栏，退出、筛选变化和操作完成后的选择状态符合预期，单批最多 50 项。
- 启动器：连续双击只产生一个受管实例；既有窗口会从最小化或后台恢复并前置；超时、陈旧状态和进程 PID 复用不会误杀普通 Codex 或无关 Node 进程。
- GitHub：弹窗覆盖新建/已有仓库、Public/Private、发布范围、写入方式、许可证、README 与主分支保护；每个选项都显示简要说明和风险。
- GitHub 安全：真实远端写入必须通过预检 ID、配置摘要与 `confirm:true`；本地隔离暂存复检在任何远端调用之前完成，密钥、私钥、超限文件和源变化会硬阻断。
- GitHub 权限：Public 文案明确任何人可查看、下载和 fork，但没有写权限的人不能直接修改原仓库；扩展不会新增协作者，也不会改变已有仓库的访问权限。

## 0.9.0 安全预览、视觉对齐与宿主切换验收范围

- 安全预览：图片仅支持 PNG/JPEG/WebP/GIF/BMP，并校验扩展名、文件头、字节数、尺寸和总像素；文本只接受 UTF-8 或带 BOM 的 UTF-16，最多 512 KiB/5000 行。
- 惰性内容：HTML、SVG、脚本与源码只返回 `text/plain` 并由 React 文本节点显示，不使用 `innerHTML`、`srcdoc`、`object`、`embed` 或 `file://`。
- 路径边界：预览只接受产出项 ID 与清单中精确登记的相对路径；绝对路径、穿越、未登记条目、链接逃逸与读取期间变化全部拒绝。
- 文件树交互：文件夹默认收起并逐层展开；支持格式的普通文件可通过单击或菜单打开预览，不支持格式保留“打开所在位置”。
- 视觉对齐：主背景为 `#181818`；嵌入态“立即扫描”右边缘与“全部类型”右边缘共用同一垂直线，状态组内部顺序、间距与尺寸保持不变。
- 宿主生命周期：从产出项切至任务、设置或其他原生页面时同步恢复宿主内容，不迁移 iframe；两种标题栏 test-id 形式均清除浏览器页签残留并保留原生窗口控制按钮。

## 0.9.1 概览删除入口与回收站兼容验收范围

- 概览操作：检测状态、上传个人 GitHub、打开位置和删除产出项按固定顺序单列显示，四个按钮同宽同高；受保护或已删除项目显示不可操作状态。

## 0.9.2 会话内删除沉底与产出项总大小验收范围

- 会话内排序：非删除项始终排在已删除项之前；优先级和更新时间只在各自状态桶内生效，刚删除或高优先级的删除项也不会上浮。
- 会话摘要：存在非删除项时，只使用非删除项计算任务组优先级和最近更新时间；任务组全部删除时才回退到删除项。
- 产出项总大小：每项持久化 `sizeBytes` 与 `sizeAggregationComplete`，完整扫描后使用递归总字节数；普通列表读取不会重复扫描目录。
- 摘要展示：正常项显示“类型 · 文件数量 · 总大小 · 版本”；统计不完整时显示“大小未知”；已删除项完全省略大小段。
- 删除语义：项目删除或路径缺失后清空 item 级大小为 `null/false`，不保留或展示删除前大小；版本、活动和来源历史继续保留。
- 旧数据迁移：文件元数据版本升级到 v2；只在首次迁移时补算仍存在且可安全扫描的项目大小，缺失或不完整项目保持未知。

## 0.9.3 全部产出已删除的任务会话隐藏验收范围

- 主列表：任务会话下没有任何非删除产出项时，整个任务会话分组不显示；底层产出记录、版本和活动日志不删除。
- 自动恢复：同一任务会话恢复或新增任一非删除产出项后，分组自动重新出现。
- 搜索与筛选：全删会话在默认、搜索和类型筛选下都保持隐藏；混合会话只命中其已删除项时仍显示该命中结果。
- 兼容性：混合会话内仍保持非删除项在前、已删除项在后；会话摘要只使用非删除项计算优先级和更新时间。
- 任务重命名：即使增量扫描读取到 0 条新产出证据，`session_index.jsonl` 的最新非空根任务标题仍同步到同任务的全部 `taskGroup.title`；SQLite 只在索引没有有效标题时回退使用，并动态探测 `threads.name/title`，优先取非空 `name`。
- 元数据隔离：纯重命名只新增或更新 `taskGroup.title/titleSyncedAt`，不改变产出项 `updatedAt`、优先级、状态、人工标记、活动、当前版本或任何历史 `version.source`；连续无变化扫描不会改写 `items.json`。
- 任务树与兜底：覆盖由 subagent 生产的多产出根任务、整个分组都已删除并隐藏的记录、仅存在于会话索引的归档任务，以及索引缺失和未知来源保留最后已知标题。

## GitHub 上传后端验收范围

- `scripts/github-publisher-self-test.mjs` 使用内存 fake adapter；不会连接 GitHub、不会调用真实 `gh` 写操作，也不会接触真实 `items.json`。
- GitHub 身份自检覆盖三类矛盾状态：`auth status` 返回失效账号、`auth status` 成功但只读 `api user` 返回 401、两条只读命令返回不同账号；三者都必须保持 `ready=false`、不泄露模拟 token，并且不得进入任何远端写入方法。
- 发布器自测中的假私钥、项目密钥和 GitHub token 由运行时片段拼接；把自测源码本身作为上传源预检时不得产生 `private-key` 误报，运行时生成的真实测试夹具仍必须被安全扫描阻断。
- 验证缺少 `gh` 是可报告的未就绪状态，且扩展声明不保存 token；验证 Public 风险、已有仓库权限不变和不授予协作者语义。
- 验证 `.git`、`.env`、私钥、凭据名、`node_modules` 与链接排除，超过 2 MiB 文本末尾 secret 仍由流式扫描硬阻断，二进制返回未做文本扫描提示，覆盖 50/100 MiB 阈值、总量/文件数限制，以及 owner/repo/branch/相对路径注入与穿越阻断。
